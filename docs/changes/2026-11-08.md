## Rust MSVC 打包链路复审与修复（builders/rust + workflow + doc/rust.md）

按"构建失败 → 冒烟有效性 → 安装卸载契约 → 体积 → CI"顺序全链路复审，证据均取自 live `channel-rust-stable.toml` 与 1.99.1 官方归档（本地解包核对），修复如下：

- **`-RustVersion` 钉旧版本必 404（致命）**：旧逻辑用 `channel-rust-stable.toml` 的 URL + 钉住的版本号重建文件名，而 stable 的日期目录只含当前版本。改为读取该版本自己的 `channel-rust-<version>.toml`（每个正式发布都有，内容不可变），URL / 日期目录 / SHA-256 一次取全；版本号不符或文件不存在立即报错。同时删掉已无用的 `FileStem` 与 URL 重建分支。
- **下载无完整性校验**：`Download-File` 新增 SHA-256 参数，对缓存命中与每次新下载都校验（channel TOML 的 `hash` 字段；xwin 用其 Release 的同名 `.sha256` 资产），失败即删除重试 3 次。原先"半截缓存文件被永久复用"的静默失败被堵住。
- **漏装官方默认组件 `rust-docs`**：官方 `[profiles] default` 为 `rustc/cargo/rust-std/rust-mingw/rust-docs/rustfmt-preview/clippy-preview`；`rust-mingw` 在 channel 中没有 `x86_64-pc-windows-msvc` 的 per-target 节（MSVC 主机上 rustup 也装不了），`rust-docs` 有且此前漏装。已补入组件清单并断言 `share\doc\rust\html` 存在。新增下载 81,270,707 字节（官方默认组件归档合计 278,465,224 字节 / 265.6 MiB）。
- **只删确定无用的 PDB（体积）**：删除本包永不调用的 `gcc-ld\{ld.lld,ld64.lld,wasm-ld}.pdb` 与 `bin\wasm-component-ld.pdb` 共 4 个文件、19,906,560 字节（18.98 MiB，1.99.1 实测）；`rustc` / `rustdoc` / `lld-link` 的 PDB 与其余文件全部保留，与官方安装内容保持一致。
- **冒烟测试从"验版本号"升级为端到端**：新增 `rustc -vV` 的 host 断言与 `rustc --print sysroot == 暂存树根`；冒烟 crate 的 `main.rs` 改为真实调用 Win32 API（`#[link(name="iphlpapi")]` + `GetNumberOfInterfaces`，该导入库不在 std 默认链接集，能链上即证明 `sdk\lib\um\x86_64` 的 `-L` 生效）；`cargo build -v` 的 rustc 命令行必须出现暂存 `rust-lld.exe`（堵住"有 VS 的 runner 上 config 被忽略也能构建成功"的假阳性）；构建产物必须实际运行并输出 `ifaces=<n>`。顺带修掉 here-string 缺尾换行导致 `cargo fmt --check` 必失败的问题。
- **安装/卸载契约**：兜底 `%USERPROFILE%\.cargo\config.toml` 的段首新增标记注释，安装替换与卸载删除都只作用于**带标记的段**——原先卸载会无条件删掉用户手写的 `[target.x86_64-pc-windows-msvc]`（自定义 linker/rustflags），属数据丢失风险；用户段现在原样保留并写日志。删除安装树里从未被 setup.iss 读取的 `.cargo\config.toml` 占位文件（安装后只留一个空 `.cargo\` 目录）；卸载追加 `RegDeleteKeyIfEmpty` 清掉 `HKCU\Software\win-env\rust` 空键。
- **CI**：`build-rust.yml` 的 `GITHUB_TOKEN` 此前只注入环境变量、脚本从未发给 API（匿名 60 次/小时，共享 runner 常 403），现由 `build.ps1` 以 `Authorization: Bearer` 显式使用并补 `User-Agent`；job 增加 `timeout-minutes: 90`。
- **链接器指向错误导致所有 cargo 构建失败（致命，CI 实证）**：`linker` 原指向 `gcc-ld\lld-link.exe`。rustc 会按链接器文件名识别 LLD 并自动前置 `-flavor link`，而该包装器又追加一份自己的 `-flavor link`，`rust-lld` 收到两份后把第二份与裸词 `link` 转发给已选定的 COFF 驱动，报 `warning: ignoring unknown argument '-flavor'` + `error: could not open 'link': no such file or directory; did you mean '/link'`——run `42483684688` 即死在此步，安装后的用户环境同样链不上。改为 `linker` 直接指向 `rust-lld.exe`（通用驱动从 `argv[1]` 正确消费 `-flavor link`），构建期冒烟 config、`setup.iss` 的 `SdkLldPath` 兜底 config、日志断言三处同步；冒烟第 3 项改为 `rust-lld -flavor link --version`。
