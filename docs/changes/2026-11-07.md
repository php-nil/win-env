# 2026-11-07

## 九条构建 workflow 增加每周错峰定时触发

- `.github/workflows/build-php.yml`、`build-pnpm.yml`、`build-git.yml`、`build-pwsh.yml`、`build-node.yml`、`build-rust.yml`、`build-postgres.yml`、`build-chromium.yml`、`build-python.yml`：保留原有 `workflow_dispatch` 与全部 inputs，新增 `schedule` 每周一次并彼此错开——php 周一 02:00 / pnpm 周一 14:00 / git 周二 02:00 / pwsh 周三 02:00 / node 周四 02:00 / rust 周五 02:00 / postgres 周六 02:00 / chromium 周六 14:00 / python 周日 02:00（均为北京时间）。cron 以 UTC 表达，YAML 注释标注对应的北京时间。
- 定时触发**不携带 inputs**（`inputs.*` 为空字符串，不取 input 的 `default`），因此逐条核查空值路径：九条 workflow 的 input 全部 `required: false`；版本类输入留空即进入"自动发现官方最新版本"分支；`draft_release` 空值被 `softprops/action-gh-release@v3` 视为未提供（默认非草稿，见其 `parseConfig`：`env.INPUT_DRAFT ? env.INPUT_DRAFT === 'true' : undefined`），带版本号 Release 与常青别名均照常发布。
- `.github/workflows/build-php.yml`：`nilpack_version` 没有自动发现逻辑，空值会拼出 `.../releases/download/v/nilpack.phar`（404）；改为 `${{ inputs.nilpack_version || '0.2' }}`，定时触发回落到 `0.2`，手动指定值时行为不变。
- 九条 workflow 新增 `concurrency`（`group: build-<env>`、`cancel-in-progress: false`），避免定时构建与手动构建并发覆盖同环境的 `build/stage` 与常青别名资产。`lint-ps1.yml`（push/PR 守卫）与 `build-opencv-shim.yml` 不加定时。
- `AGENTS.md`：项目定位与仓库结构表由"一律 `workflow_dispatch` 手动触发"改为"手动 + 每周错峰定时"；§3.1 新增触发排期表、定时触发的空值安全规则，以及 GitHub schedule 运维事实（仅默认分支生效、仓库连续 60 天无提交活动后自动停用）。
- `doc/` 九个环境文档（`php-8.5` / `pnpm` / `git` / `pwsh` / `node` / `rust` / `postgres` / `chromium` / `python`）的"触发构建"小节补充各自定时时间与定时触发下的空值行为。

本次不改动任何构建逻辑、安装器与脚本；定时构建与手动构建走完全相同的构建/发布链路。
